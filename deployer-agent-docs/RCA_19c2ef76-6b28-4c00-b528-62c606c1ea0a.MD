# RCA — Redeploy rejected: deployment_blocked (HTTP 409)

## Deployment
- deployment_id: 7b404fe4-53d4-486f-a5a5-21751fa4b4c1
- deployment_name: site-replica-316
- job_id: cb1758cd-5083-4040-8f15-16dc1867544e
- live (unaffected) run: 19c2ef76-6b28-4c00-b528-62c606c1ea0a → https://site-replica-316.emergent.host

## Symptom
The automated redeploy did not complete. The pipeline failed at the `trigger_indie` step before any deploy-run step executed.

## Exact error
```
deployer indie returned status 409:
{"code":"deployment_blocked",
 "error":"This deployment was blocked. If you believe this is a mistake, please contact support."}
(type: deployer_indie_4xx, retryable: false)
```

## Root cause
A **platform-side block** is set on this deployment. The `/v3/indie` trigger is rejected with HTTP 409 `deployment_blocked` at the authorization layer — this happens *before* `pull_source`, `build_image`, `deploy`, etc., so no build or runtime diagnostics exist (none are relevant). The response is explicitly `retryable: false`.

This is not a source-code, manifest, secret, tier, or database issue. Nothing in the app repo or deployment manifest set can change this outcome.

## Why no fix was applied / no resume attempted
- There is no deployer tool that can lift a platform `deployment_blocked` flag.
- `resume_pipeline` would re-fire the same `/v3/indie` call and return the identical non-retryable 409.
- The existing live deployment is unaffected and continues to serve traffic.

## Required action
The account owner must contact Emergent support to have the block reviewed/lifted, quoting:
- deployment_id: 7b404fe4-53d4-486f-a5a5-21751fa4b4c1
- deployment_name: site-replica-316
- job_id: cb1758cd-5083-4040-8f15-16dc1867544e

Once the block is cleared, the redeploy can be retriggered normally.
